# SubtitleCat for Jellyfin

Subtitles from [subtitlecat.com](https://www.subtitlecat.com), matched on the release name Jellyfin already knows
from your media file.

Pick a film, hit **Download subtitles**, choose Dutch, and get a `.srt` that is actually timed to your copy.

## How it matches

subtitlecat indexes by scene release name, which is the useful thing about it: `Dune.Part.Two.2024.1080p.BluRay.x264-YTS`
is a different cut from `Dune.Part.Two.2024.REPACK.1080p.WEBRip.x265-PSA`, and a subtitle timed to one will drift
against the other. So the plugin does not search by title and hope.

1. It searches for the exact release name of your file.
2. It searches again with the resolution removed. **This is the part that matters for 4K.** If your file is 2160p and
   subtitlecat only has the same group's 1080p encode, searching the full 2160p name would never surface it. Subtitles
   are timed to the cut, not the resolution, so that 1080p subtitle usually fits your 2160p file exactly.
3. If neither finds anything, it falls back to title and year, or series and `SxxEyy`.

Candidates are then scored rather than string-compared. The release group and the source carry the most weight, since
those are what predict whether the timings transfer. Resolution counts for much less, which is how a same-group 1080p
subtitle ends up ranked above a stranger's 2160p one.

For episodes the season and episode number are an absolute gate, never a weighted signal. An off-by-one episode
subtitle looks entirely plausible in the results list and is completely wrong on screen.

## What it will and will not find

**subtitlecat is a translation site, not an archive.** For most titles it holds one original subtitle, usually English,
and only stores a Dutch `.srt` once somebody has clicked *Translate* on that exact page. Until then the Dutch row is a
button, and pressing it runs the translation in the visitor's own browser against Google Translate. There is no
server-side endpoint for a plugin to call.

So this plugin offers what is already there and nothing else. In practice that is most popular titles and few obscure
ones. Availability also varies per release entry, which is why the plugin checks several candidate releases instead of
stopping at the first: for one film sampled during development, 4 of the 6 top results had Dutch and 2 did not.

Because nearly everything on the site other than the original language is generated by machine, those results are
labelled **(machine translated from English)** and ranked below any genuinely native subtitle. They are still offered,
because for most titles they are the only thing there.

## Installing

Add this repository under **Dashboard > Plugins > Repositories**:

```
https://raw.githubusercontent.com/SurfHost/jellyfin-plugin-subtitlecat/main/manifest.json
```

Then install **SubtitleCat** from the catalog and restart Jellyfin. Plugin service registrations only run at process
start, so without the restart the provider will not appear.

**Then enable it per library.** Go to **Dashboard > Libraries > (your library) > Subtitle downloaders** and switch
SubtitleCat on. A subtitle provider is inert until it is enabled there, and a plugin that is installed but not enabled
looks exactly like a plugin that does not work.

## Configuration

Everything has a working default. The ones worth knowing about:

| Setting | Default | What it does |
| --- | --- | --- |
| Accept a different resolution | on | The 2160p-to-1080p behaviour described above. Leave it on. |
| Detail pages per search | 8 | How many candidate releases to open. More finds more, at one request each. |
| Minimum match score | 40 | Higher is stricter. 40 is roughly "title and year agree". |
| Delay between requests | 1200 ms | One search makes several requests. Keep this polite. |
| Include machine-translated | on | Turning this off leaves very little. |

The config page also has a **status panel** and a **test search** box. The panel exists for one specific failure: if
subtitlecat changes its HTML, every search quietly returns nothing and the plugin looks like it is working fine on a
library of unsubtitled films. The panel tells those two apart by reporting whether pages were fetched but parsed to
nothing.

## Building

Requires the .NET 9 SDK.

```bash
dotnet build Jellyfin.Plugin.SubtitleCat/Jellyfin.Plugin.SubtitleCat.csproj -c Release
```

```bash
dotnet test Jellyfin.Plugin.SubtitleCat.Tests/Jellyfin.Plugin.SubtitleCat.Tests.csproj
```

The tests run against pages saved from the live site under `Jellyfin.Plugin.SubtitleCat.Tests/Fixtures`. The parsers are
regexes over someone else's markup, so the fixtures are the only thing standing between a site redesign and a silent
failure. If subtitlecat changes its layout, refresh the fixtures and the failing assertions will show you what moved.

To install a local build by hand, copy `Jellyfin.Plugin.SubtitleCat.dll` and `meta.json` into
`<jellyfin-config>/plugins/SubtitleCat_0.1.0.0/` and restart.

## Notes

This plugin scrapes a third-party site it has no arrangement with. The request throttle is deliberately conservative and
the User-Agent is honest rather than disguised. Please do not lower the delay to hammer them.
